# Quote a SantéVet pet insurance policy

SantéVet deliberately publishes no consumer price grid — a premium depends on breed, age and
postal code, and is only obtainable by asking. The acquisition API's `GET /rates` **is** that
rating engine, and the Toolkit API supplies the product catalogue around it.

## Before you start

- **Two different APIs, two different hosts, one partner key in the `Authorization` header.**
  - `https://acquisition.api.santevet.com` — the rating and quotation engine.
  - `https://toolkit.api.santevet.com` — the product and reference-data catalogue.
- **The acquisition API has no machine-readable specification.** It is documented only as an
  HTML reference at <https://acquisition.api.santevet.com/api/doc>, generated by
  NelmioApiDocBundle. It publishes no `operationId`s, so this skill names its operations by
  method and path. Do not expect to find them in an OpenAPI document.
- **Resolve breed identifiers first.** See `santevet-resolve-species-and-breeds.md`. The rating
  call takes integers, not breed names.

## Steps

1. **Resolve the animal.** Get the species and breed identifiers, plus `father_breed` and
   `mother_breed` for a crossbreed.

2. **Request the rate.** `GET /rates` on the acquisition host with:

   | Parameter | Type | Notes |
   |---|---|---|
   | `postal_code` | string | French/EU postal code — drives the geographic rating zone |
   | `breed` | integer | resolved breed identifier |
   | `father_breed` | integer | crossbreeds only |
   | `mother_breed` | integer | crossbreeds only |
   | `birth_date` | datetime | the animal's date of birth, which sets the age band |

   Every parameter is documented as optional, but the published `422` condition says the request
   is rejected when `postal_code` or `birth_date` is missing. Treat both as required.

3. **Branch on the status code before reading any body.** This operation has a documented status
   contract and each code means something different:

   | Status | Meaning | What to do |
   |---|---|---|
   | `200` | rates and options returned | continue |
   | `204` | **no rates available for this combination** | a business answer, not an error — tell the user this animal cannot be quoted with these details |
   | `400` | rates could not be retrieved | do not retry unchanged |
   | `422` | parameters invalid, e.g. missing `postal_code` or `birth_date` | fix the request |

   The `204` is the one agents get wrong. It is not an empty success to be retried and not a
   failure to be reported as an outage — it is SantéVet saying no product exists for that breed,
   age and location.

4. **Read the product catalogue behind the rate.** On the Toolkit host:
   - `get_rates_by_speciesSvDefContratAssuranceCollection` (`GET /species/{id}/rates`) — the
     contract definitions available for that species.
   - `getSvDefContratAssuranceCollection` (`GET /insurances`) — all contract definitions.
   - `getSvDefOptionAppliqueeAuDefContratCollection` (`GET /options`) — the cover options
     attached to a contract definition.
   - `searchSvTarifsContratCollection` (`POST /rates/search`) — search the underlying rate rows.
   - `getFractionnementCollection` (`GET /payment-divisions`) — the premium instalment plans
     (monthly, annual) the customer can choose.

5. **Check for an applicable promotion.** `getSvPromoCollection` (`GET /promotional-codes`) is
   the most filterable collection in the estate — 20 declared query parameters. The useful ones:

   - `?code=` and `?is_active=` for an exact, currently-valid code
   - `?maximumAgeInMonth[lte]=` to keep only promotions this animal is young enough for
   - `?start_date[before]=` / `?end_date[after]=` to keep only promotions valid today
   - `?components.insurance=` to keep only promotions that apply to the chosen product

6. **Present the quote.** State the premium, the instalment plan, the options included and any
   promotion applied. Say plainly that it is a quote and not a bound policy.

## Retrieving a quotation someone else created

- `GET /quotations/{id}` — by integer id.
- `GET /quotations/{uniqueId}` — by an opaque 40–60 character alphanumeric handle, which is the
  unguessable identifier used in customer-facing quote-resume links. Treat it as a secret: it
  addresses a record containing a named person's address, e-mail, phone and date of birth.
- `GET /quotations/{id}/rates` — the rates attached to an existing quotation.
- `POST /quotations/search` — paginated search with `page`, `results_per_page` and
  `filters[quotation_id|prospect_id|name|firstname|status|min_date|max_date]`. This is the only
  paginated operation in the whole SantéVet estate that uses page numbers.

## Rules

- **Stop at the quote.** `POST /quotations`, `POST /quotations/subscribe`,
  `POST /quotations/{id}/subscribe` and `PATCH /quotations/{id}/to-validate` bind a real
  insurance contract for a real person and a real animal. They are out of scope for this skill.
  Never call them without an explicit, specific human instruction to subscribe.
- **Never create or modify a prospect here.** `POST /prospects` and `PATCH /prospects/{id}` write
  a named person's address, e-mail, telephone and date of birth. Quoting does not require it.
- **Never call `POST /prospects/anonymize`.** It is an irreversible GDPR erasure operation.
- **There is no idempotency key anywhere on this API.** No write operation publishes a
  deduplication contract, so a retried subscription can bind twice. This is the strongest reason
  to keep this skill read-only.
- **Never invent a rate, a premium or a promotional code.** If `GET /rates` returns `204`, there
  is no price. Say so.
- **A quote is not advice.** Report the numbers SantéVet returns; do not recommend a formula or
  interpret cover.
- **Cache the reference data, not the rate.** Species, breeds, countries and instalment plans are
  stable. Rates are computed per animal and must not be reused across animals.
